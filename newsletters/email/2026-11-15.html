Copilot 모델 종료, 대체 모델과 예외까지 확인하기

GitHub Changelog · 발표 2026-11-13

GitHub가 일부 Copilot 모델의 12월 14일 지원 종료와 전환 조건을 안내했습니다.

AI 제작 · 편집 일러스트 · 실제 제품 화면 아님

GitHub는 11월 13일 Claude Fable 5·Haiku 4.5, Gemini 3.8 Flash·4 Argon, Grok 4.6, Kimi K3를 Copilot 전반에서 12월 14일 지원 종료한다고 예고했습니다. Fable 5.2·Haiku 5.5·Hydrogen·Carbon·Grok 4.7을 대안으로 제시했지만 Kimi K3의 대안은 추후 발표입니다. 연간 요금제 개인 구독자의 Haiku 4.5는 예외입니다. 기업용 대안의 기본 활성화도 관리자의 전체 기본값·개별 모델 차단 설정에 따라 달라집니다. 아직 모든 대상이 종료된 상태라는 뜻은 아닙니다.

AP의 관점
AP의 웹 서비스 개발 도구를 점검한다면, 모델 이름이 바뀌기 전에 같은 공개 과제로 결과·도구 호출·권한을 비교하는 실험을 제안합니다. 종료일만 적는 대신 대체 모델과 실제 사용 정책을 함께 확인할 수 있습니다.

GitHub Changelog · 발표 2026-11-13

GitHub Enterprise Server 연결이 정식 제공됐지만 클라우드 세션은 지원하지 않습니다.

AI 제작 · 편집 일러스트 · 실제 제품 화면 아님

GitHub는 11월 13일 Copilot 앱의 GitHub Enterprise Server 지원을 선택형 프리뷰에서 정식 제공으로 전환했다고 알렸습니다. 앱 1.2.0 이상에서 원격 저장소·이슈·풀 리퀘스트를 사용할 수 있습니다. 먼저 GitHub.com 또는 GHE.com 계정으로 로그인한 뒤 설정의 계정 추가에서 Enterprise Server를 선택하는 방식입니다. GHES용 클라우드 세션은 제공되지 않습니다. 저장소 연결과 클라우드 실행 가능 여부를 같은 기능으로 읽으면 안 됩니다.

AP의 관점
AP의 고객사별 개발 환경을 검토한다면, 연결할 수 있는 자료와 실행되는 위치를 별도 항목으로 확인하는 방식을 제안합니다. 사내 저장소를 읽을 수 있다는 사실만으로 컴퓨터와 독립된 작업까지 가능하다고 판단하지 않는 것이 출발점입니다.

지식베이스 이전, 원본 옆에서 먼저 검증하기

AWS Blog · 발표 2026-11-12

AWS의 이전 가이드는 읽기 전용 조사와 계획 검토부터 시작하고 새 구성을 원본과 나란히 둡니다.

AI 제작 · 편집 일러스트 · 실제 제품 화면 아님

AWS는 11월 12일 Agent Toolkit의 amazon-bedrock 스킬에 지식베이스 이전 가이드를 추가했다고 설명했습니다. 코딩 에이전트가 읽기 전용으로 구성을 조사하고 계획을 작성한 뒤, 승인 후 기존 지식베이스 옆에 새 Managed Knowledge Base를 만들거나 이전용 인프라 코드를 작성하도록 안내합니다. 실제 데이터 수집과 앱의 검색 호출 변경은 사용자에게 남는 단계입니다. 검색 결과를 검증한 다음 트래픽을 전환하며, 리전별 기능과 사용량 비용도 확인해야 합니다.

AP의 관점
AP의 교육·뉴스레터 자료 검색을 개선한다면, 원본을 바로 교체하지 않고 같은 공개 질문을 두 구성에 보내는 실험을 제안합니다. 필요한 자료가 빠지거나 권한 범위가 달라지는지 확인한 뒤 이전 여부를 판단할 수 있습니다.

AWS Blog · 발표 2026-11-11

AWS는 형식 정책의 공통 구조와 불일치를 결정적으로 계산하는 공개 엔진을 소개했습니다.

AI 제작 · 편집 일러스트 · 실제 제품 화면 아님

AWS는 11월 11일 anti-unification을 이용한 형식 정책 비교 방법을 소개했습니다. 엔진은 인코딩한 식과 명시한 동치 규칙을 읽어 공통 구조와 다른 부분을 보여주며, LLM은 비교 계산에 참여하지 않습니다. Cedar·OpenShell·CEL 등 예제를 다루지만 해당 원본 형식을 그대로 가져오는 범용 파서는 아닙니다. 여러 후보가 같은 부분에 동의해도 그 자체가 요구사항의 정답 증명은 아니며, 불일치는 정책 검증·사례·담당자 판단으로 확인하는 구분입니다.

AP의 관점
AP의 AI 교육이나 권한 설계에 참고한다면, 같은 요구를 두 방식으로 정리하고 실제 허용·거절 사례를 비교하는 실험을 제안합니다. 문구 수정과 동작 변경을 구분해 검토할 수 있습니다.

도구가 바뀔 때, 등록부도 함께 갱신하기

AWS Blog · 발표 2026-11-11

AWS의 이벤트 기반 예제는 MCP 변경을 감지해 기존 도구 등록 정보만 갱신합니다.

AI 제작 · 편집 일러스트 · 실제 제품 화면 아님

AWS는 11월 11일 Agent Registry의 도구 정보를 이벤트 기반으로 동기화하는 구조를 공개했습니다. CloudTrail의 UpdateAgentRuntime 기록을 EventBridge가 전달하고 Lambda가 MCP 서버의 최신 도구를 조회해 달라진 경우 등록 정보를 갱신합니다. AgentCore Identity가 OAuth 교환을 중개합니다. 예제는 미리 등록된 서버의 기존 기록만 수정하며 신규 기록을 만들지 않습니다. CloudTrail 전달은 약 5~15분 지연될 수 있어 즉시 동기화를 보장하는 구조는 아닙니다.

AP의 관점
AP의 웹 서비스나 Lia Select 싱가포르 커머스 연동에 참고한다면, 기능 변경 기록을 기준으로 안내와 실제 입력 형식이 일치하는지 확인하는 실험을 제안합니다. 변경이 없을 때 점검을 반복하는 방식과 구분해 볼 수 있습니다.
