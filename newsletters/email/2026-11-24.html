Search 개인화 연결 확대, 지금 제공과 예정 기능 구분

Google Blog · 발표 2026-11-23

Google은 AI Mode의 Wallet 연결을 순차 제공하고 Drive·Gemini 연결은 앞으로 몇 주 안에 확대한다고 밝혔습니다.

AI 제작 · 편집 일러스트 · 실제 제품 화면 아님

Google은 11월 23일 Search의 Personal Intelligence에 연결할 앱을 늘린다고 발표했습니다. Wallet 연결은 이날부터 순차 제공하며 Drive·Gemini 앱 지원은 앞으로 몇 주 안에 이어집니다. 사용자가 선택해 연결하고 언제든 끌 수 있습니다. Wallet 정보는 읽기만 가능하며 자금을 옮기거나 관리·투자하지 못한다고 명시했습니다. 응답에 쓰인 맥락을 보는 개인화 아이콘도 예정 기능입니다. 계정·지역의 실제 지원은 설정에서 확인해야 하며, 발표한 모든 연결과 확인 기능이 이미 동시에 제공된다는 뜻은 아닙니다.

AP의 관점
AP의 AI 교육·웹 서비스 설계에 참고한다면, 가상 정보로 연결 동의·사용한 맥락·연결 해제를 구분하는 안내표를 제안합니다. Lia Select 자료 흐름에서도 개인화에 필요한 정보와 실제 변경 권한을 나누고, 예정 기능을 현재 기능처럼 설명하지 않는 기준을 세울 수 있습니다.

Gemini 파일 분할 읽기, 필요한 페이지·구간만 살피기

Google Blog · 발표 2026-11-23

Google은 문서·시트·음성·영상의 특정 부분을 서버에서 읽는 Gemini API 제어 기능을 발표했습니다.

AI 제작 · 편집 일러스트 · 실제 제품 화면 아님

Google은 11월 23일 Gemini API의 파일 분할 제어와 Office·OpenDocument 원본 업로드 지원을 소개했습니다. 문서의 페이지 범위·해상도·텍스트 또는 이미지 계층, 시트의 탭·셀 범위·데이터·수식·시각 정보, 음성·영상의 시간 구간 등을 선택할 수 있습니다. 파일을 한 번 올린 뒤 같은 URI를 여러 차례 재사용하는 방식입니다. Gemini 4 모델 전체가 대상이지만 기존 업로드 용량·페이지 제한은 그대로입니다. 검사한 부분의 토큰이 과금되며, 범위를 줄이는 것과 무료 이용은 다릅니다. 생략한 페이지의 중요한 조건을 놓치지 않도록 읽기 범위를 정해야 합니다.

AP의 관점
AP의 문서·콘텐츠 교육에 참고한다면, 공개 예제 문서의 전체 목차를 먼저 보고 필요한 표와 주석을 함께 확인하는 실험을 제안합니다. 실제 유료 API 호출 없이도 선택 범위·해상도·빠진 근거를 기록해 부분 읽기의 이득과 누락 위험을 비교할 수 있습니다.

Google은 Canvas로 웹 앱·학습 도구·업무 계산기·글 수정을 하는 네 가지 활용법을 소개했습니다.

AI 제작 · 편집 일러스트 · 실제 제품 화면 아님

Google의 11월 23일 글은 채팅 옆의 상호작용 작업 공간인 Gemini Canvas 활용 안내입니다. 브라우저 게임·시각화 등 웹 앱 만들기, 노트·PDF를 퀴즈·카드로 바꾸기, 스프레드시트로 판매 추적기·가격 계산기·할 일 목록 만들기, 선택한 문장의 말투·구조를 수정하기를 예로 듭니다. 네 가지 사용법을 소개한 글이며 새 모델 출시나 모든 산출물의 정확성 보장은 아닙니다. 실제 계정의 기능 지원과 생성한 코드·계산·문장의 결과는 별도로 확인해야 합니다.

AgentCore 훅, 알림과 실행 차단을 같은 것으로 보지 않기

AWS Blog · 발표 2026-11-19

AWS는 Strands 기반 관리형 기본값과 실행 전후의 결정적 검사 지점을 설명했습니다.

AI 제작 · 편집 일러스트 · 실제 제품 화면 아님

AWS의 11월 19일 글은 11월 11일부터 순차 반영한 AgentCore harness의 Strands 기반 기본값과 생명주기 훅을 설명합니다. 모델·지시·도구·맥락 관리의 기본값은 발전할 수 있으며 명시한 설정이 우선합니다. 고정 경계가 필요하면 허용 도구 등을 개별 지정하도록 안내합니다. Lambda 훅은 호출 전·도구 실행 전후 등에 허용·거절을 적용할 수 있지만 SNS·EventBridge 훅은 알림이며 실행을 막지 않습니다. 이미 스트리밍한 출력은 사후 훅으로 회수할 수 없습니다. 타임아웃·오류 시 기본 실패 모드는 거절입니다.

AP의 관점
AP의 서비스 구현 교육에 참고한다면, 모의 요청에서 실행 전 검사·실행 결과·단순 알림을 나누는 실험을 제안합니다. 실제 발송·결제 없이도 거절 시 도구가 실행되지 않는지, 알림만으로 차단됐다고 착각하지 않는지 확인할 수 있습니다.
