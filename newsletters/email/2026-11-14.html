오래된 앱의 이사, AI 생성물도 검토를 거친다

AWS Blog · 발표 2026-11-13

Kuehne+Nagel 사례는 AI 컨테이너 전환과 엔지니어의 출시 승인을 함께 다룹니다.

AI 제작 · 편집 일러스트 · 실제 제품 화면 아님

AWS는 11월 13일 Kuehne+Nagel의 AWS Transform 활용 사례를 공개했습니다. 회사는 온프레미스 RHEL 애플리케이션 10개를 EKS용 컨테이너로 옮기는 작업에서 소스 분석·Dockerfile·Helm 차트 생성과 빌드·보안 검사를 활용했습니다. 복잡한 앱 4개로 방식을 검증한 뒤 전체 대상 10개를 처리했다고 설명합니다. 각 생성물은 엔지니어가 동작·보안 조건을 검토하고 운영 승격을 승인했습니다. 시간 단축 성과는 해당 고객 사례이며 모든 앱에서 같은 결과를 보장하지 않습니다.

AP의 관점
AP의 웹 서비스 이전에 참고한다면, 실행 파일이 만들어졌는지와 기존 기능이 유지되는지를 따로 확인하는 작은 이전 실험을 제안합니다. 허용된 자료와 별도 시험 환경에서 복구 경로까지 확인한 뒤 적용 범위를 판단할 수 있습니다.

02 / AI NEWS

빠른 코드보다, 느린 호출부터 찾기

AWS Blog · 발표 2026-11-13

Kiro Power 예제는 반복 DB 호출을 진단하고 묶음 처리·SQL 집계·캐시를 선택합니다.

AI 제작 · 편집 일러스트 · 실제 제품 화면 아님

AWS는 11월 13일 메인프레임에서 Java로 전환한 앱의 성능을 Kiro Power로 점검하는 예제를 소개했습니다. Power는 반복 DB 호출의 묶음 처리, Java 집계의 SQL 이전, 참조 데이터 캐시 같은 패턴을 제공합니다. 먼저 병목을 찾고 사람이 변경안을 검토·승인하는 흐름입니다. 앞선 저장 결과에 의존하거나 즉시 일관성이 필요한 작업은 무조건 묶으면 안 된다는 제한도 명시합니다. 상업적 Kiro 사용에는 구독이 필요하며 예제의 성능 개선을 다른 앱에 그대로 적용할 수는 없습니다.

AP의 관점
AP 웹 서비스에 참고한다면, 화면이 느린 이유를 모델이나 서버 크기만으로 판단하지 않고 반복 요청부터 측정하는 실험을 제안합니다. 변경 전후 결과의 동일성과 응답 시간을 함께 비교할 수 있습니다.

무엇을 만들지, 고객의 근거로 먼저 고르기

AWS Blog · 발표 2026-11-11

AWS Quick의 AI-PDLC 가이드는 고객 문제에서 우선순위·설계·시제품으로 이어지는 기록을 남깁니다.

AI 제작 · 편집 일러스트 · 실제 제품 화면 아님

AWS는 11월 11일 AWS Quick의 6개 에이전트로 구성하는 AI-PDLC 가이드를 공개했습니다. 고객 문제를 수집하고 우선순위를 정한 뒤 요구사항과 시제품으로 연결합니다. 이번 글은 발견·결정·설계·시제품의 앞 네 단계에 집중하며, 이후 구현은 Kiro 같은 코딩 에이전트가 명세를 받아 수행하는 구분입니다. 각 단계에서 사람이 판단·승인하고 결정 근거를 기록하도록 설계됐습니다. 에이전트가 문서를 만든 것만으로 제품이 검증됐다고 볼 수는 없습니다.

AP의 관점
AP의 교육 상품이나 Lia Select 싱가포르 커머스 기능을 검토한다면, 고객 불편의 원문과 기능 선정 이유를 연결하는 실험을 제안합니다. 구현 속도를 재기 전에 실제로 해결할 문제와 확인할 시제품 범위를 정할 수 있습니다.

에러가 없어도, 계산은 틀릴 수 있다

AWS Blog · 발표 2026-11-11

HyperPod 가이드는 겉으로 정상인 학습 계산의 오류를 재실행과 복제본 비교로 찾습니다.

AI 제작 · 편집 일러스트 · 실제 제품 화면 아님

AWS는 11월 11일 SageMaker HyperPod의 분산 학습에서 조용한 데이터 손상을 감지하는 방법을 소개했습니다. GPU가 그럴듯한 오답을 내고 오류를 알리지 않는 경우를 겨냥합니다. 기울기의 NaN·Inf 검사, 다른 노드 계산의 재실행 비교, 갱신 후 가중치 지문 비교를 조합합니다. 예제는 소프트웨어로 주입한 오류를 시험한 결과이며, 모든 하드웨어 오류의 탐지를 보장하지 않습니다. 의심 노드를 격리하고 확인·교체한 뒤 의심 구간 이전 체크포인트에서 재개하는 절차를 구분합니다.

AP의 관점
AP의 AI 운영 교육에 참고한다면, 작업 종료 코드가 정상이라는 사실과 내용이 맞다는 증거를 분리해 설명할 수 있습니다. 중요한 숫자는 별도 계산과 대조하는 예제부터 만드는 방식을 제안합니다.

매번 새로 만들기 전에, 재사용 근거부터

AWS Blog · 발표 2026-11-11

AWS가 문서 처리·검색·에이전트 등 23개 공개 자산의 목록과 평가 방법을 소개했습니다.

AI 제작 · 편집 일러스트 · 실제 제품 화면 아님

AWS는 11월 11일 Generative AI Innovation Center의 재사용 자산 23개를 정리했습니다. 문서 처리, RAG, 음성 상담, 에이전트 구성과 운영 도구 등을 GitHub·AWS Labs에서 공개하며 배포 안내와 샘플을 제공합니다. AWS는 품질·보안 검토와 고객 사례를 소개하지만, 가져온 구성의 권한·데이터 처리·유지보수 상태는 자신의 환경에서 확인해야 합니다. 공개 소스라는 사실과 배포에 필요한 AWS 서비스 비용은 별개의 조건입니다.

AP의 관점
AP의 콘텐츠·뉴스레터·고객 지원 도구를 개선한다면, 필요한 기능 하나에 맞는 공개 자산의 라이선스와 변경 이력을 먼저 비교하는 실험을 제안합니다. 재사용 여부도 실제 입력과 검증 기준이 맞는지 확인한 뒤 판단할 수 있습니다.
