スキルが「共通規格」になった — Agent Skillsの財団寄贈、3年ぶりのAPI新バージョン、盗まれた鍵から私たちが点検した三つのこと

Agent Skills · Anthropic · Linux Foundation · AAIF · APIバージョン · Railway · APIキー · 2026.10.23 · AP Holdings 編集部 · 15 分で読めます

韓国語の原文からAIが翻訳したものです。ネイティブによる確認は未実施です。

10月22日、AnthropicはAgent Skills標準をLinux Foundation傘下のAAIFに引き渡し、その前日にはClaude APIに2023年以来初めての新バージョンが出て、同じ日にホスティング事業者Railwayは顧客のAPIキーを含む環境変数が流出した可能性があると公表しました。性質の異なる三つのニュースを「ひとつのスキルフォルダ」の視点でまとめて読み、私たちが点検した順序を記しました。

この記事はAI(Claude)と共同で作成し、編集者が検証しました。この記事の中心にあるAnthropicは、私たちが執筆に使ったClaudeを作った会社であり、私たちの会社も社内業務用のスキルをいくつも作って使っているため、利害関係があります。そのため、会社が発表した数値は「会社が発表したもの」と表示し、良い悪いの評価ではなく、私たちが実際に点検した順序だけを記しました。特定企業への投資意見ではありません。

今週は「AIエージェントの部品」に関するニュースが3日間で3件出ました。ひとつは規格(スキル形式が一企業の手を離れて財団に移った)、ひとつはバージョン(Claude APIが3年ぶりに新バージョンを出した)、ひとつは鍵(ホスティング事業者に預けていたAPIキーが流出した可能性がある)です。別々に見れば異なるニュースですが、スキルフォルダをひとつ運用する立場から見ると、三つとも「自分のフォルダの中に何が入っていて、それが何に依存しているか」という同じ問いに集まります。前の記事NO.8(スキルが1万個になったとき)とNO.20(インストール前に点検する順序)の続編として読んでください。

1. 規格 — スキル形式が財団に移った(事実)

Anthropicは10月22日、Agent Skills標準をLinux Foundation傘下のAgentic AI Foundation(AAIF)に寄贈すると発表しました。発表文によると、寄贈の対象は標準そのものと「Agent Skills」の名称・ロゴ、GitHub組織、agentskills.ioドメインです。AAIFはAnthropicがBlock・OpenAIとともに設立した財団で、Anthropicは先にMCP(Model Context Protocol)もここに引き渡しています。

Linux Foundationのプレスリリースは、同じ日に四つのプロジェクトをまとめて受け入れたと明らかにしました。AnthropicのAgent Skills、OpenAIのOpen Responses(複数プロバイダにまたがるモデル呼び出し規格)、Hugging FaceのOpenEnv(強化学習環境の共有)、AlibabaのOpenSandbox(エージェント用サンドボックス)です。財団が管理するプロジェクトは、2025年12月の発足時の3件から10件になったと記しています。

スキルとは何かは、規格サイト(agentskills.io)が短く定義しています。スキルとはSKILL.mdファイルが入ったフォルダです。このファイルに名前と説明(最低限の項目)と指示文が入り、必要ならスクリプト・参考文書・テンプレートを同じフォルダに置きます。エージェントは起動時に名前と説明だけを読んでおき、合う仕事が来たときに指示文全体を読み、実行中にスクリプトや参考ファイルを開きます。規格はこの3段階を「段階的開示(progressive disclosure)」と呼んでいます。

規模はAnthropicが発表したものです。70以上のエージェント製品がこの形式を受け入れ(ChatGPT、Cursor、GitHub Copilot、VS Codeを例に挙げています)、公開されたスキルは約100万件、インストールは約2億8千万回だとしています。ドイツのメディアMIXEDは、この数値は会社の集計であり、独立に検証された利用者数ではないと付け加えました。私たちも同じ立場です。

運営方式も発表文にあります。Anthropic・Google・OpenAIなどのエンジニアが会社代表ではなく個人の資格で標準を管理し、リードメンテナーはDavid Soria ParraとMahesh Muragの2人です。財団の会員でなくても使え、貢献できます。そして「今後やること」として三つを挙げました。バージョン付きの正式リリース、規格変更を提案する公式手続き、そしてスキルを作り、インストールする人のためのセキュリティ指針です。MIXEDが指摘したとおり、この三つはまだ提案であって、出たものではありません。

2. バージョン — Claude APIが3年ぶりに新バージョンを出した(事実)

前日の10月21日には、Claude APIの新バージョン「2026-10-21」が出ました。Anthropicのドキュメントのバージョン一覧には2023-01-01、2023-06-01、そして今回の2026-10-21の三つしかなく、3年4か月ぶりの新バージョンです。開発者向けアカウント(@ClaudeDevs)は、新しいSDKとCLIがこのバージョンを既定で使うと知らせました(私たちはXの投稿を直接開けず、韓国のまとめサイトpromppyの要約とAnthropicの公式ドキュメントで確認しました)。

移行ドキュメントが記した変更のうち、小さなチームがすぐに直面しそうなものは次のとおりです。

  • temperature、top_p、top_kの三つのパラメータがなくなります。 既定値で送っても400エラーになります。ドキュメントは「低いtemperatureで一貫した回答を得ていたコードはその効果を失い、これに代わる設定はない」と記しています。
  • 認証ヘッダーが変わります。 新しいSDKはX-Api-KeyではなくAuthorization: Bearer形式でキーを送ります。間に置いたプロキシやゲートウェイが古いヘッダーを読んでいる場合は直す必要があります。
  • assistantメッセージにdocumentブロックを直接入れたり、userメッセージのtextブロックにcitationsを入れたりすると400エラーになります。
  • 管理APIのレスポンスのフィールド名がいくつも変わります(roles → role_ids、name → display_nameなど)。
  • Python SDKは2.0.0から新バージョンを使います。SDKとCLIのライセンスがApache 2.0に変わります。

重要なのは、旧バージョンがすぐに切れるわけではないという点です。ドキュメントは、既存のSDKは引き続き2023-06-01ヘッダーを送るので今のバージョンに留まってもよいと記しており、2023-06-01の終了日はどこにも書かれていません。「終了日がない」と「永久に維持される」は別の話なので、私たちは前者までを確認したものとして記します。

3. 鍵 — ホスティング事業者に預けたAPIキーが流出した可能性がある(事実)

同じ10月21日、アプリホスティング事業者Railwayは公式ブログにセキュリティ告知を掲載しました。要旨はこうです。その日の朝、顧客の環境変数を保存するシステムで異常な活動を検知し、調査の結果、許可のない第三者が暗号化された環境変数にアクセスした可能性があり、一部は復号された内容まで取得した可能性があるというものです。環境変数には通常、APIキーやデータベース・レジストリの接続情報が入ります。Railwayはこの事件を「AI推論プロバイダを狙ってプラットフォーム企業を相次いで攻撃する流れの一部」と見ていると書きました。

会社が取った措置は三つです。上流のプロバイダに知らせてキーを先回りして失効させ、すべてのデプロイを一時停止し、影響が確認されたアカウントにメールで知らせるとしました。利用者には、「影響は一部の利用者にとどまる可能性がある」という初期分析にもかかわらず、すべての環境変数(APIキーと非公開レジストリの資格情報を含む)を直ちに差し替え、該当サービスのログで異常な利用を確認するよう強く勧告しました。告知には被害アカウント数や流出した変数の数といった数字はありません。

この事件をめぐり、SNSや一部メディアには「盗まれた鍵は闇市場ですぐ現金になる」「蒸留用の学習データを作ろうとする需要がある」「暗号資産のウォレットから数十万ドルが抜かれた」といった話が出回っています。私たちはこのうちどれもRailwayや捜査機関の資料で確認できなかったため、この記事では「そうした主張がある」以上のことは書きません。

三つのニュースがひとつのフォルダで出会う地点(解釈)

スキルフォルダは軽いものです。SKILL.md一枚とスクリプト数本です。しかしその軽いフォルダは三つのものに寄りかかっています。

第一に、形式です。フォルダ構造と名前・説明の項目が規格に従ってはじめて、他のエージェント製品でも読めます。規格が一企業の中にあったときは「その会社が変えれば合わせて変える」でしたが、財団に移った後は「バージョンと提案手続きを見て追いかける」になります。財団が約束したバージョンリリースとセキュリティ指針が出るまでは、実のところ今と大きくは変わりません。

第二に、スクリプトが呼ぶAPIのバージョンです。スキル内のスクリプトがtemperatureを渡していたり、X-Api-Keyヘッダーを読むプロキシを経由していたりすれば、SDKを上げた瞬間にそのスキルは静かに壊れます。スキルは「インストールしたときにうまく動いた」で終わるものではなく、下にあるAPIバージョンが変わるたびに回し直さなければならないものです。

第三に、スクリプトが使う鍵がどこにあるかです。スキル自体にキーを書いていなくても、そのスキルを動かすサーバーの環境変数にキーがあり、そのサーバーがホスティング事業者にあるなら、今回のRailwayの件のように自分のフォルダとは無関係な場所で鍵が漏れることがあります。財団が「スキルを作り、インストールする人のためのセキュリティ指針」を最初の課題に挙げた理由もここにつながっていると見ています(このつながりは私たちの解釈であって、財団が明らかにした理由ではありません)。

私たちなら — スキルフォルダで点検した三つのこと(実践)

私たちの会社は社内業務用のスキル(アプリ画面のポリシー、資料分析の手順、記事の点検など)をSKILL.md形式で作って使っています。今週のニュースを受けて実際に点検した順序です。

  1. 形式の点検。 すべてのスキルのSKILL.mdにnameとdescriptionがあるか、説明が「いつこのスキルを取り出すか」を一行で言っているかを確認しました。規格が求める最低限の項目がこの二つで、エージェントが起動時に読むのもこの二つだけだからです。財団のバージョンリリースが出たら、そのバージョン番号をスキルフォルダ内の参考文書に書いておくことにしました。
  2. バージョンの点検。 スキルフォルダ内のスクリプトでtemperature・top_p・top_k、X-Api-Keyの文字列を検索しました。ひとつでも出てくれば、そのスキルは「SDKを上げる前に直すもの」リストに入れます。SDKはすぐには上げず、直すリストが空になったときに上げます。旧バージョンの終了日が告知されたら、そのとき日程を前倒しします。
  3. 鍵の点検。 スキルフォルダとリポジトリのどこにもキーが書かれていないかを再度検索し、キーの置き場所(ホスティング事業者の環境変数、シークレット管理ツール)を一覧にしました。外部事業者に預けたキーは「その事業者が破られれば一緒に漏れる鍵」として分類し、使用量アラートと支出上限を設定してあるかを確認しました。Railwayの告知が勧めた「ログで異常な利用を確認する」は、事故が起きた後ではなく、普段からアラートで受け取ってこそ役に立つと考えました。

この三つは、新しいニュースがなくても四半期に一度は回してみる価値のある点検です。NO.5で「指示は資産ではなく負債」と書きましたが、スキルフォルダも同じです。フォルダが増えるほど、形式・バージョン・鍵の三つの軸で点検するものも一緒に増えます。

このニュースで確認できなかったこと

  • Anthropicが発表した70以上のプラットフォーム、約100万スキル、約2億8千万インストールは会社の集計であり、独立した検証資料は見つかりませんでした。
  • @ClaudeDevsのX投稿の原文は直接開けず、API新バージョンはAnthropicの公式ドキュメント(バージョン一覧・移行ガイド)で確認しました。Python以外の言語のSDKの正確な新メジャーバージョン番号はドキュメントで確認できませんでした。
  • 2023-06-01バージョンの終了日はドキュメントにありません。「ない」ことまでを確認しました。
  • Railwayの事件の被害規模(アカウント数・変数の数)、攻撃主体、他のプラットフォーム侵害との関連はRailwayの告知になく、メディアとSNSの数値(ウォレットの被害額など)は確認できませんでした。
  • 参考サイトLearn:USの10月20日の記事(他人が作ったスキルを安全にインストールする方法)は公開された一覧の要約だけを読み、本文は開けませんでした。
