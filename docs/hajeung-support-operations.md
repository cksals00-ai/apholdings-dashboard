# 하자증권 B2B 담당자 페이지 운영

## 담당자에게 전달할 주소
https://www.apholdings.kr/hajeung/

회사별 B2B 안내·테스트 신청·피드백 접수에 반복 사용한다. 다른 상품 안내와 운영 고객 자료는 이 페이지에 자동으로 연결하지 않는다. 담당자에게 직접 보내는 메시지는 사용자가 발송한다.

## 현재 배포 준비 상태
안내 화면과 비공개 접수·관리자 코드 구현 완료. `hajeung/config.mjs`의 `backendEnabled:false`가 접수를 닫는다. 서버 적용과 인증 메일·스토리지 실검증을 마치기 전 true로 바꾸지 않는다.

## 서버 연결 순서
1. 운영 연결 승인 뒤 `supabase/hajeung_support.sql`, `supabase/b2b_login_rate.sql`을 순서대로 적용한다. 두 스크립트는 신규 설치용이며 중복 실행하지 않는다.
2. `supabase/functions/b2b-login/index.ts`와 `core.mjs`를 verify_jwt=false로 배포한다. 공개 로그인 메일 요청은 이 함수만 사용하며 별도 SMTP 비밀번호를 복사하지 않는다. 기존 RESEND_API_KEY 및 SUPABASE_URL/SERVICE_ROLE 환경을 사용한다. 서비스 키는 정적 클라이언트에 넣지 않는다.
3. 기존 Supabase 전체 Site URL·관리자 URL을 바꾸지 않는다. 전용 메일은 /hajeung/#token_hash=...로 돌아오며 fragment는 HTTP 요청·리퍼러로 전송되지 않는다. 페이지가 fragment를 제거한 후 verifyOtp로 일회 확인한다. 별도의 복귀 허용 URL 변경이 필요하면 사전 승인을 확인한다.
4. SQL 권한을 익명·확인되지 않은 이메일·서로 다른 두 사용자·관리자로 대조한다. private bucket, MIME image/jpeg, 최대 5MB, 고정 본인/요청/photo.jpg 경로를 확인한다.
5. 소유자가 직접 인증 메일을 요청하고 링크를 눌러 본인 접수·조회·사진·답변을 확인한다. 실제 담당자 메일로 임의 테스트 발송하지 않는다. 확인 실패 시 접수를 계속 닫는다.
6. backendEnabled를 true로 배포하고 공개 URL·기존 관리자·로그아웃 시 비공개 정보 제거를 재검증한다.

## 관리자 처리
기존 /admin/ → B2B 고객 지원. 회사·이메일을 확인하고 승인/보류/승인 불가를 선택한다. 승인 후 사람이 개인 앱 코드 발급을 실행한다. 이것은 새 보안 자격증명 발급이므로 에이전트가 실제 발급 버튼을 대신 누르지 않는다.
코드는 한 번 표시되고 서버에는 hash만 저장된다. 해당 담당자에게만 승인된 개별 채널로 전달한 뒤 표시를 닫는다. 코드를 분실했거나 기존 앱 계정과 이메일이 충돌하면 자동 덮어쓰기하지 않고 별도 계정 관리 절차로 처리한다.
발급된 앱 계정은 role=담당자, demo=true. 운영 권한·실제 메일 발송 권한을 주지 않는다. 테스트 계정들은 공통 가상 자료 영역을 사용하며 회사별 운영 테넌트를 자동 생성하지 않는다.

수정 요청은 접수/확인 중/처리 중/추가 정보 요청/완료로 관리한다. 비공개 답변은 웹에 저장되며 자동 이메일 답신·상태 알림은 발송하지 않는다. 최근 최대 200건 목록을 표시한다. 오래된 기록 조회·대규모 고객 관리가 필요하면 서버 페이지네이션을 추가하고 완료로 숨기지 않는다.

## 보관·삭제
본문·사진·승인 이력은 공개하지 않는다. 삭제 요청은 담당자가 alfred.park@apholdings.kr로 접수하고 관리자가 보관 의무·앱 계정 영향을 확인 후 처리한다. 이 구현은 영구 삭제 UI나 자동 삭제를 제공하지 않는다. 로그인 남용 방지용 email/IP hash 카운터는 7일 경과분을 다음 요청 시 정리한다.

## 유료화와 출시
iOS/Android의 상품·가격·사용 제한·구독·체험·복원·만료 동작을 실제 대조하기 전 동등성 완료라고 안내하지 않는다. 현재 문구는 준비 기준이며 판매 상품·가격을 만들어내지 않는다. Apple TestFlight와 정식 스토어 공개는 구분한다. Google Android 정식 공개 후 실제 설치 가능한 링크로 교체한다.

## 검증 범위
Node 입력·메일 라우팅·실패 처리·사이트 연결 테스트, PGlite 실제 SQL RLS/발급 격리/기존 운영 계정 보호 테스트. 로컬 브라우저 데스크톱 및 360/390px iframe 렌더링 검사. 실제 휴대폰·운영 이메일·스토리지 업로드는 서버 활성화 후 별도 검증한다.
