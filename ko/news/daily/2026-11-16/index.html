AI 보안 검사, 허용과 실행을 나눠 관리하기

GitHub Changelog · 발표 2026-11-13

GitHub가 저장소 AI Scan의 설정을 API로 관리하는 공개 프리뷰를 안내했습니다.

GitHub는 11월 13일 조직과 저장소의 AI Scan 설정에 repository_scan 항목을 추가했다고 발표했습니다. 조직이 끄면 개별 저장소가 켤 수 없고, 조직이 켜면 저장소가 상속하되 개별 해제가 가능합니다. 기업 정책이 허용하지 않으면 활성화 요청은 거절됩니다. 설정을 켜는 것만으로 검사가 시작되지는 않습니다. 쓰기 권한 사용자가 별도로 실행하며 검사마다 GitHub Code Security AI 크레딧을 사용합니다. 조직 소유 공개 저장소와 해당 보안 상품을 갖춘 비공개·내부 저장소가 대상이며, Enterprise Server는 지원하지 않습니다.

AP의 관점

AP의 웹 서비스 개발 절차에 참고한다면, 보안 기능 허용 여부와 실제 검사 실행·결과 확인을 따로 기록하는 방식을 제안합니다. 설정만 완료된 상태를 검사 통과로 오인하지 않도록 공개 예제 저장소의 관리 흐름부터 설계해 볼 수 있습니다.

02 / AI NEWS

길게 일하는 AI, 작업 공간의 경계를 지키기

AWS Blog · 발표 2026-11-12

AWS가 세션 격리를 유지하면서 실행 자원과 데이터 연결을 확장한 AgentCore runtime 업데이트를 소개했습니다.

AWS는 11월 12일 차세대 AgentCore runtime을 발표했습니다. 세션마다 별도 Firecracker 마이크로 가상머신과 신원·정책·감사 기록을 유지하며, 실행 자원은 최대 8 vCPU·32GB로 확장되고 최대 10GB 컨테이너 이미지를 지원한다고 설명했습니다. 파일시스템을 동적으로 연결해 작업을 저장하는 기능도 소개했습니다. 시작 시간과 메모리 효율 개선 수치는 AWS가 제시한 조건의 설명으로 읽어야 합니다. 실행 환경의 격리가 모델 답변의 정확성이나 모든 업무의 자동 완료까지 보장하는 것은 아닙니다.

AP의 관점

AP의 교육 자료 처리나 고객별 웹 작업을 설계한다면, 입력 자료와 작업 파일이 어느 세션에 속하는지 먼저 정리하는 실험을 제안합니다. 처리량을 늘리기 전에 고객 간 자료 분리와 작업 종료 뒤 보존 범위를 확인하는 데 참고할 수 있습니다.

03 / AI NEWS

숙련자의 정비 지식, AI가 먼저 모으고 사람이 판단하기

AWS Blog · 발표 2026-11-12

Natera의 장비 지원 사례는 자동 진단 보고서와 엔지니어의 실제 확인을 분리합니다.

AWS는 11월 12일 Natera의 실험실 장비 운영 지원 시스템 SWARM을 소개했습니다. 배경 에이전트가 지원 요청을 분석해 원인 가설·점검 순서·신뢰도 표시를 담은 보고서를 만들고, 별도 대화형 에이전트가 엔지니어의 후속 검토를 돕습니다. 장비 설명서와 과거 요청을 지식으로 사용하며, 환자를 식별할 수 있는 정보는 모델이나 검색 색인에 넣지 않는다고 설명합니다. 자동 첫 응답의 적용 범위는 수리 완료율이 아닙니다. 실제 해결 내용과 진단을 대조해 자료와 개별 스킬을 개선하는 고객 사례입니다.

AP의 관점

AP의 교육·웹 서비스 문의 대응에 참고한다면, 공개된 가상 문의로 답변 초안과 담당자의 해결 기록을 비교하는 실험을 제안합니다. 답변이 빨랐는지와 문제가 해결됐는지를 따로 측정하고, 빠진 안내 자료부터 보완하는 접근을 검토할 수 있습니다.

04 / AI NEWS

익숙한 모델 실행 도구, 다른 AI 칩으로 넓히기

AWS Blog · 발표 2026-11-12

SGLang-Neuron이 공개돼 SGLang의 실행 흐름을 AWS Trainium에서도 사용할 수 있게 됐습니다.

AWS는 11월 12일 RadixArk와 Annapurna Labs가 협력한 SGLang-Neuron의 공개 제공을 알렸습니다. 별도 플러그인이 SGLang을 Trainium에 연결하고 모델 실행은 네이티브 PyTorch를 사용합니다. 기존 서버 인터페이스와 생성 API 흐름을 유지하면서 하위 칩 실행 경로를 바꾸는 구조입니다. 안내 예제는 Trainium3 인스턴스와 전용 Deep Learning Container를 전제로 합니다. 모든 모델과 설정의 지원을 뜻하지 않으며, 검증된 구성은 프로젝트 문서에서 확인해야 합니다. 공개 도구라는 이유로 클라우드 자원 비용이 없어지는 것도 아닙니다.

AP의 관점

AP의 서비스 구현을 위한 실행 환경을 비교한다면, 같은 공개 과제에서 지원 모델·처리 시간·전체 자원 비용을 함께 기록하는 방식을 제안합니다. 익숙한 호출 형식을 유지할 수 있다는 점과 실제 이전 비용을 분리해 판단할 수 있습니다.

05 / AI NEWS

Copilot 좌석 배정, 기업 앱 권한으로 연결하기

GitHub Changelog · 발표 2026-11-10

기업 GitHub App이 Copilot 좌석 관리 API를 호출할 수 있도록 세분화된 권한이 추가됐습니다.

GitHub는 11월 10일 Enterprise GitHub App의 기업 단위 Copilot 좌석 관리 API 지원을 알렸습니다. 어떤 사용자와 기업 팀에 Copilot 좌석을 배정할지 관리하는 기능입니다. 이를 위해 앱에 Enterprise Copilot license management라는 새 세분화 권한을 사용합니다. 이 공지는 앱을 통한 라이선스 배정 관리 경로에 관한 것으로, 모든 구성원에게 좌석이 자동 제공되거나 구독 비용이 없어졌다는 발표가 아닙니다. 실제 적용 전에는 기업 계정의 권한과 기존 배정 정책을 확인해야 합니다.

AP의 관점

AP의 고객사 AI 교육 계정 운영을 설계한다면, 교육 대상과 실제 사용 권한의 목록을 대조하는 절차를 제안합니다. 담당자 승인과 회수 기준을 먼저 정하고, 시험 계정의 배정 기록을 남기는 방식으로 운영 범위를 작게 확인할 수 있습니다.
