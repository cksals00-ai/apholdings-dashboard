01 / AI WORKSPACE

Gemini, 대화 안에서 문서·PDF 직접 편집 지원

Google 공식 블로그 · 발표 2026-10-29

문서 생성에서 수정·검토까지 대화 안으로 들어오며, 결과물을 완성하는 방식이 달라집니다.

Google은 Gemini 앱에서 문서·PDF·프레젠테이션·스프레드시트·코드 등을 생성하고 미리 보며 직접 수정하는 기능을 발표했습니다. PDF 미리보기와 편집은 웹·모바일에서, Google Docs·Sheets·슬라이드·Markdown·TXT·코드는 웹에서 지원합니다. Gemini 앱이 제공되는 모든 언어의 이용자에게 제공한다고 밝혔습니다. 기기별 지원 형식 차이는 그대로 남습니다.

AP의 관점

AP의 AI 교육은 첫 초안 생성 뒤 사람이 근거와 표현을 수정하는 과정까지 다룰 필요가 있습니다. 콘텐츠·뉴스레터 제작에서도 파일 형식별 수정 가능 범위와 최종 PDF 검토를 안내하면 결과물의 활용도가 높아집니다.

02 / SINGAPORE AI

Google, 싱가포르 연구 거점과 보건 AI 협력 확대

Google 공식 블로그 · 발표 2026-10-29

현지 연구진·의료기관과 데이터 주권을 함께 다루는 AI 도입 모델이 확장됩니다.

Google은 싱가포르에 현지 연구자·엔지니어로 구성된 Google Research 거점을 설립하고 NUS·NTU 등과 협력한다고 밝혔습니다. MedGemma 기반 현지 의료 솔루션 연구와 데이터 주권을 강조하며, NUHS와 AI co-clinician 도구를 평가하고 있습니다. Google.org·DeepMind는 보건 연구 연합에 700만 달러를 기여하며 이 중 100만 달러는 PathGen 지원입니다. 의료 효과가 확정됐거나 한국에서 같은 서비스가 출시됐다는 의미는 아닙니다.

AP의 관점

Lia Select의 싱가포르 커머스와 AP의 서비스 구현에서도 현지 기관·사용자 맥락을 이해하는 접근이 중요합니다. 의료 기능을 상거래에 적용한다는 뜻이 아니라, 데이터를 어디에 두고 누구와 검증할지 먼저 정하는 협력 방식에서 참고할 점이 있습니다.

03 / FRONTIER MODELS

Gemini 4 Carbon, 사이버 방어 파트너부터 제한 제공

Google DeepMind 공식 발표 · 발표 2026-10-28

새 모델의 높은 평가 점수와 지금 이용할 수 있는 범위는 구분해야 합니다.

Google은 Gemini 4 Carbon의 사이버 방어·장기 작업 성능 향상을 발표했습니다. 취약점 탐지·검증·수정 평가 결과를 제시했으며 일부 외부 사이버 평가는 가드레일 없이 수행됐다고 명시합니다. 먼저 일부 사이버 방어 조직에 제공하고 Fairwind 프로그램의 신뢰 파트너로 접근을 넓힐 계획입니다. 일반 개발자·기업·소비자 대상 제공은 향후 계획으로, 한국이나 싱가포르에서 누구나 즉시 사용할 수 있는 출시는 아닙니다.

AP의 관점

AP의 교육·서비스 제안에서는 모델 순위보다 실제 이용 자격과 고객 업무에서 검증한 결과가 우선입니다. 제한된 보안 평가의 성적을 모든 운영 환경의 안전성으로 확대하지 않고 권한·복구·검증 절차를 함께 설명해야 합니다.

04 / AGENT OPERATIONS

Microsoft Foundry, Copilot 실행 기반 공개 미리보기

Microsoft Foundry 공식 블로그 · 발표 2026-10-28

에이전트를 오래 안정적으로 실행하려면 모델 외에 도구·권한·진행 기록이 필요합니다.

Microsoft는 Foundry Agent Service의 Copilot harness를 공개 미리보기로 소개했습니다. 재사용 스킬·인증과 승인을 설정한 도구·실행과 위임·버전 관리된 에이전트 정의를 묶는 관리형 실행 기반입니다. Hosted agents의 장기 작업 복원 기능은 정식 제공으로 구분했습니다. 중단 후 원래 입력으로 재시작하므로 앱이 진행 상태를 저장하고 외부 작업의 중복을 막아야 합니다. 미리보기는 지원 지역·모델·제한을 별도로 확인해야 하며 모델 추론과 외부 서비스 비용은 무료가 아닙니다.

AP의 관점

AP가 구현하는 웹·서비스나 뉴스레터 자동화에서도 생성 성공보다 재시작 후 중복 없이 마무리되는 구조가 중요합니다. 실행 기반이 제공하는 복원과 개별 업무가 저장해야 할 승인·전송 상태를 나누어 설계할 수 있습니다.

05 / AI GOVERNANCE

Microsoft, 에이전트별 신원·최소 권한·관찰 가능성 강조

Microsoft Security 공식 블로그 · 발표 2026-10-28

AI를 더 많이 연결할수록 각 에이전트의 담당자와 접근 범위가 보여야 합니다.

Microsoft Security는 에이전트 확산에 따른 보안 책임을 다룬 글에서 에이전트별 관리 가능한 신원, 필요한 범위의 접근 권한, 데이터 분류·보호를 강조했습니다. 어떤 에이전트가 존재하고 누가 소유하며 무엇에 접근하고 실행하는지 관찰해야 한다는 권고입니다. 신제품 출시나 새로운 의무 규정이 아니라 공급업체의 운영·보안 가이드입니다.

AP의 관점

AP의 고객 서비스 구축에서는 공용 계정 하나로 여러 자동화를 연결하기보다 업무별 소유자·접근 범위·중지 방법을 정리하는 편이 유용합니다. AI 교육에서도 도구 연결 전에 개인정보와 실행 권한을 판단하는 사례를 포함할 수 있습니다.
