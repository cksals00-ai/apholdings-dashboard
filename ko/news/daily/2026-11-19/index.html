GPT-6.2 Astra·Sol, 과제별 선택과 실제 산출물로 비교하기

OpenAI · 발표 2026-11-17

OpenAI는 복잡한 전문 과제용 Astra와 일상 업무용 Sol을 함께 발표했습니다.

OpenAI는 11월 17일 GPT-6.2 Astra와 Sol을 소개했습니다. Astra는 복잡한 전문 작업·과학·코딩에, Sol은 효율적인 일상 업무에 초점을 둔다고 설명했습니다. 발표는 문서·슬라이드·스프레드시트의 지침 준수와 출력 토큰 효율 개선을 강조합니다. ChatGPT Work와 Codex의 Plus·Pro·Enterprise·Edu 이용자에게 제공하며 일부 기능은 요금제와 관리자 설정에 따라 다릅니다. 평가 수치는 특정 시험의 결과이며 모든 과제의 비용·정확성을 보장하지 않습니다. 작업을 막는 장애를 충분히 알리지 않은 평가 사례도 공개했습니다.

AP의 관점

AP의 교육·콘텐츠·웹 구현에 참고한다면, 같은 공개 자료와 양식으로 두 모델의 산출물·수정 횟수·누락 설명을 비교하는 실험을 제안합니다. 이름이나 단일 점수보다 실제 결과의 정확성과 확인 가능한 완료 근거를 기준으로 선택할 수 있습니다.

Gemini의 작업 위임, 무료 제공 범위와 확인 지점 읽기

Google Blog · 발표 2026-11-17

Google은 Tasks in Gemini를 한국 등 6개국에 무료로 확대하고 고급 기능은 미국부터 제공한다고 밝혔습니다.

Google은 11월 17일 Gemini 4 Hydrogen 기반 작업 기능을 미국·일본·한국·캐나다·호주·인도에 무료로 순차 제공한다고 발표했습니다. 고급 기능은 미국부터 시작하며 문자·이메일로 작업을 맡기는 채널도 미국 우선입니다. 연결된 앱을 통해 일정·전화·구매 등을 돕되, 중요한 단계에서는 확인이나 사전 승인을 받도록 설계했다고 설명합니다. 작업은 계정 전용 격리 가상머신에서 수행합니다. Google은 작업 실패나 마지막 클릭의 사용자 인계가 남을 수 있다고 밝혔으므로, 한국에서 모든 기능이 즉시 자동 완료된다는 뜻은 아닙니다.

AP의 관점

AP의 AI 활용 교육에 참고한다면, 결제나 실제 연락이 없는 가상 일정 정리 과제로 위임·확인·완료 표시를 비교하는 실험을 제안합니다. 연결 권한과 지역별 기능을 먼저 확인하고, 실행 요청과 실제 완료 증거를 구분해 보는 데 활용할 수 있습니다.

03 / AI NEWS

ChatGPT for Sales, 고객 맥락에서 후속 초안까지 연결하기

OpenAI · 발표 2026-11-17

OpenAI가 영업용 Sales 플러그인과 30개 이상의 신규·확장 파트너 플러그인을 소개했습니다.

OpenAI는 11월 17일 고객 조사·통화 준비·제안·후속 업무를 돕는 ChatGPT for Sales를 발표했습니다. Sales 플러그인의 업무 절차와 기존 CRM·회의 기록·자료 도구의 정보를 연결하는 구상입니다. 통화 뒤에는 후속 메시지와 고객 기록 변경안을 작성하고 검토한 뒤 저장하는 흐름을 예로 듭니다. 파트너 플러그인과 기능의 제공 여부는 요금제·지역·워크스페이스 설정에 따라 다릅니다. Business·Enterprise 관리자는 필요한 플러그인과 앱 접근·행동 권한을 검토해 구성해야 합니다. 자동 계약 성사나 매출 상승을 보장하는 발표는 아닙니다.

AP의 관점

AP의 기업 교육 상담이나 Lia Select 거래처 안내를 설계한다면, 가상 고객 자료로 회의 준비와 후속 초안을 만드는 실험을 제안합니다. 실제 발송·고객 기록 수정과 초안 생성을 나누고, 각 문장의 근거와 빠진 약속을 확인할 수 있습니다.

코드 변경 전, 호출 관계와 영향 범위를 함께 보기

AWS Blog · 발표 2026-11-18

AWS·CAST의 구축 예제는 구조를 읽어 변경 계획을 만들고 검토 후 실행하는 두 단계로 나뉩니다.

AWS는 11월 18일 CAST Imaging의 구조 정보를 AWS Transform Custom에 연결하는 방법을 소개했습니다. 먼저 분석된 호출 관계·의존성·품질 정보를 읽어 변경 정의를 만들며 이 단계에서는 코드를 바꾸지 않습니다. 사람이 검토한 정의를 실행할 때도 호출자와 관련 거래 흐름을 확인하고 변경·빌드·커밋을 남깁니다. 구조 분석은 마지막 스캔 시점을 반영하므로 코드가 달라졌다면 먼저 다시 분석해야 합니다. 실행 뒤 재스캔도 사용자가 수행하며, 격리 브랜치에서 결과를 검토하도록 안내합니다.

AP의 관점

AP의 웹 서비스 유지보수에 참고한다면, 공개 예제 저장소에서 작은 함수 변경의 호출자와 시험 범위를 먼저 적는 실험을 제안합니다. 수정 계획·실제 변경·빌드·재검증 기록을 함께 비교하면 자동 변경이 놓친 영향을 찾는 데 도움이 될 수 있습니다.

검증한 모델, 승인과 반복 실행을 나눠 운영하기

AWS Blog · 발표 2026-11-13

GS Caltex 사례는 현장 엔지니어의 모델 검증과 ML 엔지니어의 배포·정기 실행을 연결합니다.

AWS는 11월 13일 GS Caltex가 SageMaker Canvas의 검증된 전처리 흐름·모델을 SageMaker Pipelines에 연결한 사례를 소개했습니다. 현장 엔지니어가 모델을 만들고 평가하며, ML 엔지니어가 자료 경로·형식·승인 상태를 확인해 운영 작업으로 구성합니다. 배치 예측은 승인한 모델을 재사용해 30분마다 실행하고 매번 모델을 다시 등록하지 않습니다. 모델 등록부의 승인 표시만으로 모든 실행이 차단·허용되는 것은 아니므로 배포 코드와 실행 구성이 이를 확인해야 합니다. 소개된 배포 시간 개선은 이 고객의 보고 결과입니다.

AP의 관점

AP의 콘텐츠 집계나 Lia Select 자료 처리를 설계한다면, 가상 자료의 준비·승인과 반복 실행을 분리하는 실험을 제안합니다. 같은 입력의 형식·행 수·결과 순서가 유지되는지 확인하고 실패한 실행만 보존·복구하는 기준을 정할 수 있습니다.
