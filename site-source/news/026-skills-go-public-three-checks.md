> 이 글은 AI(Claude)와 함께 작성했고 편집자가 검수했습니다. 이 글의 중심에 있는 앤트로픽은 우리가 글을 쓰는 데 쓴 Claude를 만든 회사이고, 우리 회사도 사내 업무용 스킬을 여러 개 만들어 쓰고 있어 이해관계가 있습니다. 그래서 회사가 발표한 수치는 「회사가 발표한 것」으로 표시하고, 좋다 나쁘다는 평가 대신 우리가 실제로 점검한 순서만 적었습니다. 특정 기업에 대한 투자 의견이 아닙니다.

이번 주에는 「AI 에이전트의 부품」에 관한 소식이 사흘 사이에 세 건 나왔습니다. 하나는 규격(스킬 형식이 한 회사 손을 떠나 재단으로 갔다), 하나는 버전(Claude API가 3년 만에 새 버전을 냈다), 하나는 열쇠(호스팅 업체에 맡겨 둔 API 키가 새 나갔을 수 있다)입니다. 따로 보면 다른 뉴스지만, 스킬 폴더 하나를 운영하는 입장에서 보면 셋 다 「내 폴더 안에 무엇이 들어 있고, 그것이 어디에 의존하나」라는 같은 질문으로 모입니다. 앞선 글 NO.8(스킬이 만 개일 때)과 NO.20(설치 전에 점검하는 순서)의 후속으로 읽어 주시면 됩니다.

## 1. 규격 — 스킬 형식이 재단으로 갔다 (사실)

앤트로픽은 10월 22일, Agent Skills 표준을 리눅스재단 산하 Agentic AI Foundation(AAIF)에 기부한다고 발표했습니다. 발표문에 따르면 기부 대상은 표준 자체와 「Agent Skills」 이름·로고, GitHub 조직, agentskills.io 도메인입니다. AAIF는 앤트로픽이 Block·OpenAI와 함께 세운 재단으로, 앤트로픽은 앞서 MCP(Model Context Protocol)도 여기에 넘긴 바 있습니다.

리눅스재단 보도자료는 같은 날 네 개 프로젝트를 한꺼번에 받았다고 밝혔습니다. 앤트로픽의 Agent Skills, OpenAI의 Open Responses(여러 제공사에 걸친 모델 호출 규격), 허깅페이스의 OpenEnv(강화학습 환경 공유), 알리바바의 OpenSandbox(에이전트용 샌드박스)입니다. 재단이 맡은 프로젝트는 2025년 12월 출범 때 3개에서 10개가 됐다고 적었습니다.

스킬이 무엇인지는 규격 사이트(agentskills.io)가 짧게 정의합니다. **스킬은 SKILL.md 파일이 든 폴더**입니다. 이 파일에 이름과 설명(최소 항목)과 지시문이 들어가고, 필요하면 스크립트·참고 문서·템플릿을 같은 폴더에 둡니다. 에이전트는 시작할 때 이름과 설명만 읽어 두었다가, 맞는 일이 들어오면 그때 전체 지시문을 읽고, 실행 중에 스크립트나 참고 파일을 엽니다. 규격은 이 세 단계를 「점진적 공개」라고 부릅니다.

규모는 앤트로픽이 발표한 것입니다. 70개 이상의 에이전트 제품이 이 형식을 받아들였고(ChatGPT, Cursor, GitHub Copilot, VS Code를 예로 들었습니다), 공개된 스킬이 약 100만 개, 설치가 약 2억 8천만 회라고 했습니다. 독일 매체 MIXED는 이 수치가 회사 집계이며 독립적으로 검증된 이용자 수가 아니라고 덧붙였습니다. 우리도 같은 입장입니다.

운영 방식도 발표문에 있습니다. 앤트로픽·구글·OpenAI 등의 엔지니어가 회사 대표가 아니라 개인 자격으로 표준을 관리하고, 리드 메인테이너는 David Soria Parra와 Mahesh Murag 두 사람입니다. 재단 회원이 아니어도 쓰고 기여할 수 있습니다. 그리고 「앞으로 할 일」로 세 가지를 들었습니다. 버전이 붙은 정식 릴리스, 규격 변경을 제안하는 공식 절차, 그리고 **스킬을 만들고 설치하는 사람을 위한 보안 지침**입니다. MIXED가 짚은 대로 이 셋은 아직 제안이지 나온 것이 아닙니다.

## 2. 버전 — Claude API가 3년 만에 새 버전을 냈다 (사실)

하루 앞선 10월 21일에는 Claude API의 새 버전 「2026-10-21」이 나왔습니다. 앤트로픽 문서의 버전 목록에는 2023-01-01, 2023-06-01, 그리고 이번 2026-10-21 세 개만 있어, 3년 4개월 만의 새 버전입니다. 개발자용 계정(@ClaudeDevs)은 새 SDK와 CLI가 이 버전을 기본으로 쓴다고 알렸습니다(우리는 X 게시물을 직접 열지 못했고, 국내 모음 사이트 promppy의 요약과 앤트로픽 공식 문서로 확인했습니다).

마이그레이션 문서가 적은 변경 가운데 작은 팀이 바로 부딪힐 만한 것은 다음입니다.

- **temperature, top_p, top_k 세 파라미터가 사라집니다.** 기본값으로 보내도 400 오류가 납니다. 문서는 「낮은 temperature로 일관된 답을 얻던 코드는 그 효과를 잃으며, 이를 대신하는 설정은 없다」고 적었습니다.
- **인증 헤더가 바뀝니다.** 새 SDK는 X-Api-Key 대신 Authorization: Bearer 형식으로 키를 보냅니다. 중간에 둔 프록시나 게이트웨이가 옛 헤더를 읽고 있으면 손봐야 합니다.
- assistant 메시지에 document 블록을 직접 넣거나 user 메시지의 text 블록에 citations를 넣으면 400 오류가 납니다.
- 관리 API의 응답 필드 이름 여러 개가 바뀝니다(roles → role_ids, name → display_name 등).
- Python SDK는 2.0.0부터 새 버전을 씁니다. SDK와 CLI의 라이선스가 Apache 2.0으로 바뀝니다.

중요한 것은 **옛 버전이 바로 끊기지 않는다**는 점입니다. 문서는 기존 SDK가 계속 2023-06-01 헤더를 보내므로 지금 버전에 머물러도 된다고 적었고, 2023-06-01의 종료 날짜는 어디에도 쓰여 있지 않습니다. 「종료일이 없다」와 「영원히 유지된다」는 다른 말이므로, 우리는 전자까지만 확인한 것으로 적습니다.

## 3. 열쇠 — 호스팅 업체에 맡긴 API 키가 새 나갔을 수 있다 (사실)

같은 10월 21일, 앱 호스팅 업체 Railway는 공식 블로그에 보안 공지를 올렸습니다. 요지는 이렇습니다. 그날 아침 고객 환경변수를 저장하는 시스템에서 이상 활동을 감지했고, 조사 결과 **허가받지 않은 제3자가 암호화된 환경변수에 접근했을 수 있으며 일부는 복호화된 내용까지 얻었을 수 있다**는 것입니다. 환경변수에는 보통 API 키, 데이터베이스와 레지스트리 접속 정보가 들어갑니다. Railway는 이 사건을 「AI 추론 제공사를 노리고 플랫폼 회사들을 잇달아 공격하는 흐름의 일부」로 보고 있다고 썼습니다.

회사가 한 조치는 세 가지입니다. 상위 제공사에 알려 키를 선제적으로 폐기하도록 했고, 모든 배포를 일시 중지했으며, 영향이 확인되는 계정에 이메일로 알리겠다고 했습니다. 이용자에게는 「영향이 일부 이용자에 그칠 수 있다」는 초기 분석에도 불구하고 **모든 환경변수(API 키와 비공개 레지스트리 자격 증명 포함)를 즉시 교체하고 해당 서비스의 로그에서 이상 사용을 살피라**고 강하게 권고했습니다. 공지에는 피해 계정 수나 유출된 변수 수 같은 숫자가 없습니다.

이 사건을 두고 SNS와 일부 매체에는 「훔친 키가 암시장에서 바로 현금이 된다」, 「증류용 학습 데이터를 만들려는 수요가 있다」, 「가상자산 지갑에서 수십만 달러가 빠져나갔다」는 이야기가 돌고 있습니다. 우리는 이 가운데 어느 것도 Railway나 수사 기관의 자료로 확인하지 못했으므로, 이 글에서는 「그런 주장이 있다」 이상으로 쓰지 않습니다.

## 세 소식이 한 폴더에서 만나는 지점 (해석)

스킬 폴더는 가볍습니다. SKILL.md 한 장과 스크립트 몇 개입니다. 그런데 그 가벼운 폴더가 세 가지에 기대고 있습니다.

첫째, **형식**입니다. 폴더 구조와 이름·설명 항목이 규격을 따라야 다른 에이전트 제품에서도 읽힙니다. 규격이 한 회사 안에 있을 때는 「그 회사가 바꾸면 따라 바꾼다」였고, 재단으로 간 뒤에는 「버전과 제안 절차를 보고 따라간다」가 됩니다. 재단이 약속한 버전 릴리스와 보안 지침이 나오기 전까지는, 사실 지금과 크게 다르지 않습니다.

둘째, **스크립트가 부르는 API의 버전**입니다. 스킬 안의 스크립트가 temperature를 넘기고 있거나 X-Api-Key 헤더를 읽는 프록시를 거치고 있다면, SDK를 올리는 순간 그 스킬은 조용히 깨집니다. 스킬은 「설치했을 때 잘 돌았다」로 끝나는 것이 아니라, 밑에 깔린 API 버전이 바뀔 때마다 다시 돌아 봐야 하는 물건입니다.

셋째, **스크립트가 쓰는 열쇠가 어디에 있나**입니다. 스킬 자체에 키를 적어 두지 않았더라도, 그 스킬을 돌리는 서버의 환경변수에 키가 있고, 그 서버가 호스팅 업체에 있다면, 이번 Railway 사건처럼 내 폴더와 무관한 곳에서 열쇠가 샐 수 있습니다. 재단이 「스킬을 만들고 설치하는 사람을 위한 보안 지침」을 첫 과제로 든 이유도 여기에 닿아 있다고 봅니다(이 연결은 우리의 해석이지 재단이 밝힌 이유가 아닙니다).

## 우리라면 — 스킬 폴더에서 점검한 세 가지 (실전)

우리 회사는 사내 업무용 스킬(앱 화면 정책, 자료 분석 절차, 글 점검 등)을 SKILL.md 형식으로 만들어 쓰고 있습니다. 이번 주 소식을 받고 실제로 점검한 순서입니다.

1. **형식 점검.** 모든 스킬의 SKILL.md에 name과 description이 있는지, 설명이 「언제 이 스킬을 꺼낼지」를 한 줄로 말하는지 확인했습니다. 규격이 요구하는 최소 항목이 이 둘이고, 에이전트가 시작할 때 읽는 것도 이 둘뿐이기 때문입니다. 재단의 버전 릴리스가 나오면 그 버전 번호를 스킬 폴더 안 참고 문서에 적어 두기로 했습니다.
2. **버전 점검.** 스킬 폴더 안의 스크립트에서 temperature·top_p·top_k, X-Api-Key 문자열을 검색했습니다. 하나라도 나오면 그 스킬은 「SDK 올리기 전에 고칠 것」 목록에 넣습니다. SDK는 당장 올리지 않고, 고칠 목록이 비었을 때 올립니다. 옛 버전의 종료일이 공지되면 그때 일정을 당깁니다.
3. **열쇠 점검.** 스킬 폴더와 저장소 어디에도 키가 적혀 있지 않은지 다시 검색했고, 키가 놓인 곳(호스팅 업체의 환경변수, 비밀 관리 도구)을 목록으로 적었습니다. 외부 업체에 맡긴 키는 「그 업체가 뚫리면 같이 새는 키」로 분류해, 사용량 알림과 지출 한도를 걸어 두었는지 확인했습니다. Railway 공지가 권고한 「로그에서 이상 사용 살피기」는 사고가 난 뒤가 아니라 평소에 알림으로 받아야 쓸모가 있다고 봤습니다.

이 세 가지는 새 소식이 없어도 분기마다 한 번은 돌려 볼 만한 점검입니다. NO.5에서 「지침은 자산이 아니라 부채」라고 썼는데, 스킬 폴더도 같습니다. 폴더가 늘수록 형식·버전·열쇠 세 축에서 점검할 것이 함께 늡니다.

## 이 소식에서 확인하지 못한 것

- 앤트로픽이 발표한 70개 이상 플랫폼, 약 100만 스킬, 약 2억 8천만 설치는 회사 집계이며 독립 검증 자료를 찾지 못했습니다.
- @ClaudeDevs의 X 게시물 원문은 직접 열지 못했고, API 새 버전은 앤트로픽 공식 문서(버전 목록·마이그레이션 안내)로 확인했습니다. Python 외 다른 언어 SDK의 정확한 새 메이저 버전 번호는 문서에서 확인하지 못했습니다.
- 2023-06-01 버전의 종료 날짜는 문서에 없습니다. 「없다」까지만 확인했습니다.
- Railway 사건의 피해 규모(계정 수·변수 수), 공격 주체, 다른 플랫폼 침해와의 연관은 Railway 공지에 없고, 매체와 SNS의 수치(지갑 피해액 등)는 확인하지 못했습니다.
- 참고 사이트 Learn:US의 10월 20일 글(남이 만든 스킬을 안전하게 설치하는 법)은 공개된 목록 요약만 읽었고 본문은 열지 못했습니다.
