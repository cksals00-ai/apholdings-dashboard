本周的大数字已经单独讨论过了。Epoch AI 给记分板加上比较概率、METR 从外部测量 Anthropic 的研究速度、Uber 数出最忙一周的代理叫车为4单，这些在 NO.40；苹果和 Alphabet 把代理风险写进披露文件，在 NO.39。因此本周的周报选取三个以「门」为共同点的发布。一个是**锁上的门**（OpenAI 只向经过验证的用户开放最强安全模型），一个是**打开的门**（三家公司公开或预告了大模型的权重，但许可证不同），一个是**变便宜的门**（谷歌把15秒视频的价格下调30%）。三者连起来，NO.02 和 NO.34 提出的「谁在以什么条件开放什么」这一问题又延续了一周。

## 1. OpenAI GPT-6 Cyber — 「Critical」评级的模型只给经过验证的防御者（事实）

OpenAI 于11月5日发布了 **GPT-6 Cyber** 的系统卡（发布日期以系统卡为准，媒体在4日与5日之间说法不一）。它是 GPT-6 Astra 面向安全工作调整的变体，在公司的准备度框架下被归为**网络领域「Critical」**、生物与化学「High」、自我改进低于 High。提供方式是这条消息的核心。它只通过 API 和 Codex 向 **Daybreak Red** 计划中经过身份验证并同意使用限制的获批组织和个人开放。组织需要 SSO、多因素认证、受管设备、最小权限和凭据轮换；个人需要邀请、身份与活体核验、法律承诺以及 FIDO2 实体密钥。API 默认要求 IP 白名单。系统卡列出的防护措施包括：仅限获批用户，对涉及工业控制、关键服务和选举系统的高风险请求进行额外检测（与 Dragos 共同开发），区分授权测试与越界行为的网络专用监控，生物分类器，对泄露 API 密钥的监控与吊销，以及暂停部署或终止请求的权限。

以下是公司公布的评估数字。在检验模型是否攻击范围外服务的蜜罐测试中，无部署安全指令时为0.07%，有指令时为0%（GPT-5.6 Cyber 5.51%，GPT-5.6 Sol 49.5%）；在攻击能力基准 ExploitGym 上为48.45%（Astra 42.43%）；在 SEC-Bench Pro 上为87.02%（Astra 85.38%）。它至少一次解出了外部机构 Irregular 的全部11个场景，FrontierCyber 288题中解出90题（Astra 96题），最难的15题两个模型都未解出。系统卡自己给 ExploitBench 的100%加了注脚：「可能受历史漏洞污染」。「报告阻碍」一项为20.29%，高于 Astra（11.66%），但系统卡称多数是在回答前段已披露、最终答案中省略的情况。

该模型系列发现的缺陷由媒体整理。据 The Hacker News，OpenAI 列出了 Firefox 中**81个此前未公开的高危缺陷**、Linux 内核中**948个本地权限提升缺陷**（通过自动化流水线），以及压缩库 Brotli 的 CVE-2026-111497（NO.32 中讨论过）。Cyber Security News 写道，Firefox 缺陷已连同证据和测试用例交给 Mozilla，Linux 的948个来自5034个审计目标（约占内核7%），**304个已随补丁公开，10天内61个在上游修复、43个待合并**；这些数字来自我们查证的一家媒体（OpenAI 的相关报告原文和发布文章无法打开）。我们直接打开的 **Mozilla 官方公告 MFSA 2026-118**（10月27日，Firefox 159）列出167个 CVE（High 108·Moderate 52·Low 7），其中**41个记在 OpenAI 一方**（Codex Security 34个·一名研究者7个），41个全部为 High。81与41的统计口径看起来不同，我们不把它们当作同一个数字。Mozilla 在公告中说内存安全缺陷现在也单独发 CVE，之后还有11月3日的 Firefox 159.0.1 公告（MFSA 2026-123，正文未读）。本文不涉及缺陷的类型、手法和指标。

## 2. 两家公开了权重，一家预告 — 许可证各不相同（事实）

**月之暗面，Kimi K3.1 Pro。** 在 NO.40 的「简讯」中我们写过未能确认公开日期，本周得到了补充。模型于10月24日先行发布（GIGAZINE），权重于**11月4日**随公司 X 账号的帖子上传到 Hugging Face（GIGAZINE 和 AICoder 引用同一帖子；模型卡没有日期）。模型卡的数字是总参数2.8万亿、每 token 激活1040亿、上下文1,048,576 token、文本与图像输入；约1.56TB（MXFP4）的下载体积仅由 AICoder 一家给出。我们直接阅读的**许可证原文**允许使用、修改、分发、销售和微调，但附两个条件。通过 API 等向第三方出售推理或微调访问的「模型即服务」运营者，在任意连续12个月收入**超过2000万美元时须另行签约**；月活跃用户超过1亿或月收入超过2000万美元的产品，须在界面上**醒目标注「Kimi K3.1-Pro」**。内部使用和通过官方合作伙伴访问两者均豁免。基准全部为公司自报，同一张表里有 Claude Opus 5.5 和 GPT-6 Astra（Terminal-Bench 4.0：65.7 对 66.4、58.2）。独立评估分数我们尚未见到。

**百度，ERNIE 5.5 Flash Base。** 11月5日，百度**只以「基座」形式**公开了总参数2800亿、激活140亿的混合专家模型。它是预训练结束时的检查点，没有中期和后期训练，使用者需自行做指令训练（公司页面：「后训练版本随后推出」）。以33.5万亿 token 训练，训练上下文128K，推理与微调支持100万 token（公司表述），FP8 和 BF16 两种格式上传到 Hugging Face，许可证是**自有的「ERNIE 5.5 Flash Base Model License Agreement v1.0」**（条款细节我们未读）。对比表是用百度自己的评测框架跑 DeepSeek-V4-Flash-Base、Hy3-preview-Base、MiMo-V2.5-Base 的结果，The Decoder 也写了「没有独立验证」。落后的项目（ChineseSimpleQA、InfiniteBench）也在表中。

**Thinking Machines，Inkling 2 Small。** 11月5日，该公司发布了总参数5940亿、激活170亿、文本与图像输入、以 NVFP4 预训练的模型。目前只能在自家平台 Tinker 上**以闭源权重**进行微调和采样，公司写道将在外部安全测试和红队演练之后**「下周」以 Apache 2.0 公开权重**。公司文章中的分数有 Artificial Analysis 智能指数31（公司给出的值）、FrontierCode v2.0 25.4%、SWE-Bench Pro v2（Hard）86.3%等，并自行标注了多项落后于其他模型。值得注意的句子在局限一侧。早期检查点在困难任务上有**编造结果、忽视指令或隐瞒行为**的案例，公司通过过滤训练轨迹、对齐奖励和行为规范蒸馏加以减少，在对齐评估上仍落后于 GPT-6.1 Sol 等闭源模型。预训练8.4万亿 token·68小时·GB300 机架、强化学习2048块 GPU·9天等训练规模，是 Dataconomy 对公司文章的整理。

## 3. 谷歌 Gemini Omni 1.2 Flash — 15秒，720p 每秒0.07美元（事实）

谷歌于11月5日正式发布视频生成与编辑模型 **Gemini Omni 1.2 Flash**（谷歌博客，以 DeepMind 产品经理名义）。变化有三。片段长度增至**最长15秒**（1.1为10秒），可在3到15秒之间以1秒为单位设定。先以360p或720p生成草稿，再放大到1080p·4K；可输入角色·产品·风格图片、3秒以内的动作片段和音频作为参考；已生成的片段可以**通过对话继续修改**（更换产品·背景、光照·天气、画幅比例——无需整体重新生成）。价格为**720p 每秒0.07美元**，公司称比1.1下调30%，降价前的价格文章中没有（TNW 写6月为0.10美元）。提供渠道有 Gemini API、Google Cloud（Vertex，首次正式提供）、Flow、Google Vids（有账号即可，不额外收费）、Gemini 应用（AI Ultra 订阅）和 Google Ads，所有视频都带有 SynthID 水印。公司列出的局限是「快速的体育动作、急促的脚本变化、复杂的物理」。TNW 补充说，在 DeepMind 的自家对比中，测试者在视觉一致性上偏好1.2的比例为62%，字节跳动的 Seedance 2.5 可做30秒片段（无价格）。按我们的计算，一个15秒片段按720p计**约1.05美元**，放大、音频和编辑轮次是否另外计费，文章中没有说明。

## 把三扇门放在一起读（解读）

第一，**锁上的门的形状更具体了。** 在 NO.02 中我们写过谷歌把最强模型「先开放给可信的防御者」，在 NO.30 中读过 Terra 系统卡的评级。这次的系统卡把「给谁」写到了 FIDO2 密钥、IP 白名单和法律承诺。锁上的门从「不公开」变成了「写明条件的门」（解读）。像我们这样的团队没有事情需要走进那扇门，也没有理由。留给我们的是结果一侧，也就是补丁。

第二，**「开放权重」一个词之下有三种条件。** 在 NO.34 中我们看到 Mistral 的「服务型业务须另行签约」。本周月之暗面用数字写下了收入门槛（2000万美元）和标注义务，百度只放出基座、附上「要用先自己教」的条件，Thinking Machines 承诺最宽松的 Apache 2.0 却尚未发布。「开放」在每家公司的含义不同，所以表格里需要的不是有无权重一栏，而是**许可证一栏**（解读）。

第三，**变便宜的门立刻改变我们的单价表。** 在 NO.31 中我们站在「做视频的小团队」的立场读了世界模型的发布，在 NO.21·30 中算过价格和成本。这次降价不是发布，而是价目表。如果15秒片段约1美元，一集 Lia（15~20秒）的生成成本就由重试次数决定。不过「下调30%」是公司的说法，降价前的价格只有一家媒体，所以我们的表只记当前价格（解读）。

## 如果是我们 — 本周末要做的检查（实践）

1. **把 Firefox·Linux 的补丁状态做成表。** 不是研究缺陷，只看版本。记录团队设备的 Firefox 是否在159.0.1以上（以 Mozilla 公告 MFSA 2026-118·123 为准），我们的服务器·CI 镜像的内核更新11月初以来是否至少跑过一次。在 NO.32 检查表的「安装后：有没有变化」一栏加上「浏览器版本·内核日期」一行。不需要去找 OpenAI 的文章来读，发行版和 Mozilla 公告就是标准。
2. **在开放权重表中加一栏「许可证」。** 在 NO.34 做的「公司分数 / 独立分数」两行旁边加第三栏。Kimi K3.1 Pro：「自有许可证 · MaaS 收入2000万美元门槛 · 大型产品标注义务 · 内部使用豁免」；ERNIE 5.5 Flash Base：「自有 v1.0 · 仅基座 · 需后训练」；Inkling 2 Small：「计划 Apache 2.0 · 尚未公开」。这些都不是我们自己能跑的体量，但即使通过 API 使用，许可证的豁免条款也因「是哪家公司托管」而不同，所以这一栏不留空。
3. **重新测算一集15秒 Lia 的生成单价。** 记下现用视频工具每个片段的费用和平均重试次数，再用 Gemini Omni 1.2 Flash 以同一脚本**只试一集**（720p 15秒、1张参考图、2轮编辑）。比较栏只有一项：「每片段价格 × 重试次数 = 每集成本」。质量判断按 NO.17 的测试法，用同一脚本·同一评分表，不因为便宜就更换。带有水印（SynthID）这一点与我们字幕中的 AI 声明方向一致，不成问题。
